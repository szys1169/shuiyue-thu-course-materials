## 一、Agent 和 Skill 是什么

为了更好地理解，让我们先说明一些基础概念。

### 1. API

API 是软件之间发送请求和返回结果的接口。可以把它理解为服务窗口：一方按照约定提交请求，对方按照约定返回结果。

在使用 AI 的过程中，我们在对话框里输入的内容，最后会通过 API 发给模型服务商；服务商生成结果后，再以符合 API 约定的形式返回给我们，这就是调用 API 的过程。

### 2. API Key 和 api_url

刚才我们只强调了调用 API 的输入和输出过程。实际上，调用 API 时还要解决下面几个问题：

首先，我要去哪里调用这个 API？不可能全网搜索，所以需要给出具体地址，这个地址就是 `api_url`，看起来通常很像一个网址。

其次，模型服务商不能让任何人随意调用 API，所以需要身份验证。这个凭证就是 API Key，服务方据此识别你是否有权限使用。

有了上面的基础概念，下面就进入正题：

### 3. Skill

Skill，中文就是“技能”，可以简单理解为一套可复用的提示词、资料和工作方法。我们提前准备好这些内容，在 AI 进行某些工作时交给它，让它了解情况并按照约定工作。

Skill 的结构一般是一个 `SKILL.md`，旁边还可以有参考资料、模板和程序文件夹。每次调用该 Skill 时，`SKILL.md` 中的内容会提供给 AI，之后 AI 再根据具体情况读取其他文件夹中的内容。这里的 `md` 是 Markdown 格式的文件，如果你不了解它，可以把它当成一种文本文档。

举个例子，假如我经常需要做ppt，用于数学教学，那我就需要：
- 比较统一的风格
- 数学公式的书写能力
- 统一的架构

当我和 AI 说清楚这些需求之后，AI 或许能生成得还不错，但是每次生成 PPT，我都需要重新说明这些事情，太麻烦了。这时候，我就需要一个 Skill。

Skill 里面的 `SKILL.md`，要写清楚这个 Skill 是用来生成数学教学 PPT 的，以及我们有哪些具体要求。为了方便统一，我可能还会给出一些模板、图片素材（比如校徽），再把这些素材放到 `SKILL.md` 旁边的文件夹里。

简而言之，Skill 就是告诉模型，在某种特定的情况下该如何做，以及有哪些需要注意的地方。

### 4. Agent

Agent 通常译作“智能体”。大家对于智能体并没有一个特别统一的定义，所以这里我给后文的 Agent 下一个不太严格的定义：**Agent 是 AI 执行任务的系统。**

举个例子，Codex 就是一个 Agent。对于这类官方的桌面 Agent，我们也常把承载它的运行环境叫作 Harness。它有很多 Tool，给了模型执行任务的能力，比如直接生成文件、写代码、打开软件等。除了给予模型操控电脑的能力外，Harness 同时也能增强 AI 完成任务的能力。

一般而言，我们可以看到的 Agent 主要做下面两件事，或者是这两件事的组合：

- 给 AI 一些 Tool，让 AI 能做本身做不了的事情；
- 通过资料、流程、反馈和检查，增强 AI 在某方面的任务表现。

在某种意义上，你可以把agent当成一个围绕ai展开的软件

## 二、Agent 和 Skill 有什么用

小学二年级政治老师就教过我，思考问题要从“是什么”“为什么”“怎么做”三个角度去考虑。在解答完“是什么”之后，我们迎来了下一个问题：为什么要使用 Skill 和 Agent？

### 1. 它知道了你具体要什么

“整理得好一点”很模糊，“按定义、结论、适用条件和例题整理，并保留出处”就明确很多。

模型面对模糊要求时，需要猜测你的偏好。Skill 把反复出现的要求保存下来，减少了这部分猜测，也减少了每次重新组织流程时的遗漏。

### 2. 实际操作能力

查看新发布的文档，需要搜索或读取资料的工具；生成一份文件，需要写入工具。

Agent 中的工具给了模型实际操作的能力。没有相应工具时，在 Skill 中写“请联网查询”也不会让网络访问能力凭空出现。

### 3. 全方位能力的提升

其实我们现在日常使用的 AI 工具，很多都可以算作某种 Agent，哪怕是 DeepSeek 网页端，也可能在背后接入了工具和任务流程。

合适的 Agent 会给模型带来全方位的任务能力提升。

这里的“全方位”不是说模型参数突然变大了，而是模型获得了一个更完整的工作环境。模型原本只能根据当前上下文生成回答；加入 Harness 以后，它可以获得工具、文件、外部资料、长期规则、任务状态和结果反馈。这样一来，它不仅能“想”，还可以“查、算、写、跑、看结果、再修改”。这些环节组合起来，才构成了完整的任务能力。

比如，让 AI 修改程序时，普通对话可能只能给出一段代码；带有 Harness 的 Agent 可以先读取项目，找到相关文件，修改代码，运行测试，根据报错继续修复，最后汇报改了什么。增强来自模型、工具、环境、流程和反馈的组合。

### 4. 特定能力的提升

这方面和第三条是类似的，我以我最近开发的数学研究智能体举例。

它不一定让模型突然学会新的数学定理，但可以把数学研究中原本分散的工作串起来：检索论文，整理定义，生成小规模例子，运行计算，搜索反例，比较已有结论，组织证明草稿，再把每一步的依据保存下来。

例如研究一个组合数学猜想时，智能体可以先读取问题定义，再自动生成小规模数据并检查模式；发现疑似规律后，搜索相关文献；如果找到候选证明，就逐行列出使用的假设，并用程序验证边界情况。最终的数学判断仍然需要人来审核，但研究者可以把更多精力放在提出问题、选择方向和检查关键步骤上。

所以，Agent 增强的通常是“完成复杂任务的整体能力”，而不是简单地给模型增加一条知识。它能不能真的增强，还要看工具是否合适、流程是否清楚、反馈是否可靠。

## 三、去哪里下载/配置skill和agent

直接询问自己的 AI 就好，让它去 GitHub 查找相关的项目；如果有合适的，再让它配置到本地。使用第三方 Skill 或 Agent 前，要先看清楚它包含哪些文件、程序和权限要求。

例如，给一批文件统一加日期，规则清楚时一个小程序就够了。整理多份结构不同的讲义，则需要根据内容判断如何分类，可以让模型参与。Agent 的多轮执行也会增加时间和调用成本，复杂度需要有实际收益。



## 四、如何做一个 Skill

有时候我们会有自己的需求，比如想做一个“水月风格 Skill”，或者为比赛搭建一个专用 Skill。那么，如何做一个 Skill 呢？

首先，如果需求非常简单，直接把需求说明白，让 AI 完成就好。

下面是一个大概的流程：

### 1. 明确定位

先搞明白要做的 Skill 用来干什么，至少需要确定三件事：

- 它负责什么任务。
- 什么时候应该使用，什么时候不应该使用。
- 有哪些必须遵守的要求。

这里很重要的一件事，是说明白“何时该用，何时不该用”。成熟的 Harness 可能会自动读取目录下的 Skill，上面的信息能帮助 Harness 判断当前任务是否需要调用该 Skill。

### 2. 编写提示词

Skill 是怎么发挥作用的？我们可以勉强用提示词工程来概括。所以在编写 Skill 之前，还是要先回忆一下 Skill 的架构。

`SKILL.md` 是 AI 每次调用 Skill 时都会读取的主要说明文件，而其他文件通常在需要时才读取。

这里我们要回答一个问题：为什么不每次都把所有提示词都交给 AI，而只是按需挑选一部分？

首先，如果每次都把全部提示词交给 AI，Token 成本会比较高；其次，提示词太多可能反而让 AI 抓不住重点，导致输出变差。不过，对于较小的 Skill，每次全部读取也未尝不可。

所以我们需要分清楚一件事：哪些提示词每次都必须读，哪些内容可以按需读取？

这样思考之后（当然也可以让 AI 帮你思考），我们基本可以得到 Skill 的框架：`SKILL.md` 要写什么内容，文件夹内放哪些文件，以及这些文件分别承担什么作用。

接下来具体完成时，我倾向于建议“AI 初稿＋人工审核”。不少提示词 AI 已经写得很好，我们无需全部自己写；对于那些不容易描述清楚的部分，再手动补充。

### 3. 数据的获取

前面的描述可能会让你以为，提示词就是我们和 AI 对话的内容。但在 Skill 里面，还有一类材料是具体的领域数据。

举个例子，假如小明想做一个“清华吃饭” Skill，给人提供今天吃什么的建议。那问题来了：这个 Skill 最难的部分可能不是设计一套完善的提示词，而是提供清华有哪些食堂、有什么好吃的东西等数据。

那么，如果我要做一个需要专有数据的 Skill，应该怎么做？

首当其冲的就是人工录入。虽然这句话似乎什么都没说，但确实有效。

举个例子，我前段时间在做编程智能体 Classmate 的 Skill。由于 DSA 课程相对比较困难，我们考虑对 DSA 课程进行能力强化，方式就是加入大量困难知识点的通俗解释，而这些解释是我一个个敲进去的。

其次是 AI 提炼加人工审核的方式。也就是你给 AI 提供一些内容，让 AI 把这些内容提炼成 Skill 内可用的资料。举个例子，我现在要做一个数学研究 Skill，研究方向是代数几何，就可以把大量代数几何文献交给 AI，让 AI 提炼论文中的思路和方法，整理成合适的资料，之后再人工审核一遍。

### 4. 让 AI 创建技能

如果你之前看过一个 Skill，可能会产生一个疑问：Skill 里的结构虽然大部分是自然语言，但好像夹杂着一些计算机格式；而我们前面准备的提示词和数据基本都是自然语言，这是为什么呢？

这是因为剩下那一点把内容编写成标准 Skill 格式的工作，完全可以交给 AI 来做。

类似地，你可能还会担心：数据很多时，AI 能不能识别哪些内容是需要的？

实际上，我们会用 RAG 等方式来处理这些数据。不过也无需过度担心，这一部分可以先交给 AI；如果你已经熟悉这些方法，那你多半不是本篇攻略的主要受众。

让我们回到正题：完成材料整理之后，直接让 AI 创建技能就好。现在大部分 Harness，比如 Codex，本身就会带一个用于生成 Skill 的技能。


### 5. 检查与测试

大概看一看 AI 生成的 Skill 有没有和预期不一样的地方，再进行一些测试，看看是否满足需求。

如果有问题，就让 AI 更新，或者重新修改提示词和数据。


实际写一个复杂一点的 Skill 时，往往不是做完第 2、3 步再去做第 4、5 步，而是第 2、3 步完成一部分，就先生成或更新 Skill，跑一跑测试。



## 五、搭建自己的 Agent

skill是相对简单的，agent复杂的多，如果想要搭建一个复杂一点的agent，基本还是有一定的计算机能力的需求。这里我简单介绍两类agent的搭建。

### 1. 先在现有产品里配置

对零基础读者，最容易上手的方式，是利用 Codex 这类已经具备工具执行能力的产品，围绕自己的任务补充规则、资料和技能。

继续用课程资料助手举例，可以按下面的顺序做。

**第一步，新建工作文件夹。** 例如 `course-helper`，在里面建立 `materials` 和 `outputs`，分别保存输入材料与生成结果，再用 Codex 打开这个文件夹。

**第二步，让 AI 写项目说明。**

```text
请在当前项目创建 AGENTS.md，记录课程资料助手的工作约定：
读取 materials 中用户指定的材料，将结果保存到 outputs。
保留原始文件，不覆盖原材料。
保留重要结论的适用条件，区分原文和补充解释。
交付前检查文件、章节覆盖和来源，列出待确认内容。
```

`AGENTS.md` 是给现有 Agent 的项目说明，不是创建 Agent 的程序，也不会自动生成一个子 Agent。Codex 有对应的指令发现规则；在项目中启动新任务后，应确认规则已经加载。[OpenAI 的 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

**第三步，加入需要的 Skill。** 例如前面创建的 `course-review`。项目规则记录“这个项目怎么工作”，Skill 记录“这类任务怎么做”，临时要求则直接写在这次提问里。

**第四步，确认工具可用。** 普通文本需要文件读取工具，扫描材料可能需要文字识别，生成特定格式需要对应软件。让 AI 先检查是否能处理一小份材料，不要一次扔进所有文件。

**第五步，发出具体任务。**

```text
使用 course-review 整理 materials 中我指定的第一章讲义。
将结果保存为 outputs/chapter-01.md。
标明来源章节，保留定理条件。
完成后检查覆盖范围，告诉我文件位置和待确认内容。
```

**第六步，打开产物验收。** 确认文件真实存在，再抽查内容。发现问题后，判断是这次要求没说清、技能方法不完善，还是工具没有正确读取材料。

这样，你就配置了一个围绕课程资料工作的助手。运行基础由产品提供，你负责把自己的需求变成清楚的任务约定。


### 2. 做独立 Agent 的开发

这里再次提及那个假设：我默认读者的计算机水平较低。这样的话，独立 Agent 的开发确实比较困难，但也不是不能通过“许愿式编程”来实现。

做一个独立的 Agent，比较重要的一件事是必须设计好它的内部运行流程。

换句话说，需要想明白用户开始使用后，整个系统会依次发生什么。如果你能把这件事想清楚，并且向 AI 描述清楚，还是有可能实现的。当然，实现过程中还会有很多其他困难，比如 Token 消耗、修复 Bug 等，这里就不再展开。


## 六、常见问题

### 1. skill，未必能够增强能力

我们的很多的skill，之所以诞生的原因是因为之前的ai能力太差了，当ai的能力提升之后，这些skill就不再是有用的，甚至可能是负担。

所以在使用/设计skill的使用，一定要多考虑一个问题，用了这东西会比直接问ai强吗？我设计的提示词会不会成为负担

### 2. Skill 不就是提示词吗

最简单的 Skill 主要就是文字说明。它额外提供了用途描述、可复用的目录结构、参考资源和按需加载方式。如果要求只有一句话，直接放在提问里也可以。

### 3. 技能是不是越多越好

保留常用、用途清楚的技能即可。重复和冲突会增加选择难度。

而且，如果 Skill 保留在 Harness 内部，每次回答问题前，Harness 都可能检查是否有 Skill 可以调用。这会增加一定的上下文成本；如果 Skill 写得不好，也可能让 AI 抓不住重点，反而影响表现。
