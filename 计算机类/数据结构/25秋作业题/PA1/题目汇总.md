# CST 1-1-1 filename

---

#### **描述**

助教在批改作业时发现同学们提交的文件名都很任性，所以决定统一规范一下。在动手之前他想知道，将文件名 A 转换为 B 至少需要多少时间；如果超过 K 个时间单位，便干脆放弃。

为了度量转换的时间成本，我们约定仅允许以下两种编辑操作，且它们各需一个单位的时间：

1. 在第 ii 个位置插入一个字符 XX ：...Si−1SiSi+1...⇒Si−1XSiSi+1......S_{i-1}S_iS_{i+1}... \Rightarrow S_{i-1}XS_iS_{i+1}...
2. 删除第 ii 个字符 ...Si−1SiSi+1...⇒Si−1Si+1......S_{i-1}S_iS_{i+1}... \Rightarrow S_{i-1}S_{i+1}...

#### **输入**

共包含 3 行。

第 1 行包含三个整数 N、M、K：文件名 A 的长度、文件名 B 的长度、时间成本的阈值。

接下来的2行，分别给出原始字符串 A 和目标字符串 B。

#### 输出

仅1行，给出将文件名由A转换为B所需的最小时间成本；如果超过K，则输出-1。

#### **输入样例**

```
10 11 5
9873007613
87300676513
```

- 此样例就是第 1 个测试点。
- 本课堂的编程作业中，对于非全 int 输入的题目，有的会把一个样例作为第 1 个测试点方便调试。

#### **输出样例**

```
3
```

- 注：参考答案的每一行都有换行符，最后一行也有换行符。但 OJ 比对文本时一般会忽略行末空格和文末空行。

#### **数据范围**

n, m ≤ 501000

k ≤ 100

文件名中的字符都是可见 ASCII 字符（33 ≤ ASCII码 ≤ 126）。

#### **资源限制**

时间限制：0.6 sec

内存限制：64 MB

#### **提示**

[动态规划]

# CST 1-1-2 Interview-old

---

### **描述**

某公司在对应聘者做过一轮笔试之后，从中选出 n 人继续进行面试，每位应聘者被分配了一个整数ID。

为公平起见，组织者决定利用会议室外的圆桌，按以下方法“随机”确定面试顺序：第一个到达的应聘者在圆桌周围任意选择一个位置坐下；此后到达的每位应聘者都从前一应聘者出发，沿逆时针方向围圆桌走过 m 人（前一应聘者算作走过的第 1 人，同一人可能经过多次），并紧邻第 m 人右侧就座；所有应聘者到齐后，从最后到达者出发，绕圆桌以顺时针方向为序进行面试。

![](../附件/ebf6c11c9abc9d574467d4583506addb6943f452.png)

这里假定应聘者到达的时刻互异，且相对的就坐位置确定后，左、右两人之间总能插入一把椅子。

试编写一个程序，确定面试顺序。

### **输入**

共2行。

第1行包含两个整数， n和m。

第2行包含n个整数，表示先后到达的n个应聘者的ID。

### **输出**

共1行。以空格分隔的n个整数，分别表示顺次进行面试的应聘者的ID。

### **输入样例**

```
5 3
6 7 8 9 10 
```

### **输出样例**

```
10 6 8 9 7
```

### **限制**

1≤n≤1061 \leq n \leq 10^6

1≤n∗m≤1071 \leq n*m \leq 10^7

输入的ID保证在int类型的范围内。

时间：0.6 sec

空间：256 MB

### **提示**

● 可以使用数组，按时间逆序处理，从最后到达的人开始，依次确定所在的位置

● 每次只需向前跳过m个“已经有人”的位置，就可以找到上一个到达的人所在的位置，将这个位置标记为“此时还没有人”

● 需要确保，在较低的时间复杂度内，找到m个“已经有人”的位置并跳过。

● 一种方式是，将约1000个座位分为一组(1000大约是n的最大范围的平方根），维护每一组内“已经有人的位置个数”，可在sqrt(n)的时间复杂度内跳过m个位置

● 如果喜欢更直接的思路，也可以使用链表来解决本题，注意：一次性new或delete大量节点，比逐个new、delete节点要节省时间。

# CST 1-2-1 Gift

---

#### **题目描述**

小 Z 是你的好朋友，不久之后将是他的 nn 岁生日，你想要为他准备一份惊喜。这是你为小 Z 过的第一次生日，不满足于只准备一份礼物，你想要为小 Z 之前的每一次生日，也就是 1 周岁、2 周岁、...、n−1n-1 周岁和这次的 nn 周岁生日各准备一份礼物。

在冥思苦想了若干天后，你产生了足量的礼物灵感；又经过了若干天的考量后，你将每份礼物的候选方案筛到了 2 个。也就是说，对于小 Z 的第 ii 周岁生日 (1≤i≤n)(1\le i\le n)，你已经确定了两个候选的礼物，它们的价格分别为 c1i,c2i{c_i^1, c_i^2}。你最终会从这两个礼物中挑选**恰好** 1 个送给小 Z。

你用于购买这 nn 份礼物的总预算为 PP。你想要知道，**一共有多少种礼物方案的总花费不超过** PP。不难理解，每一个礼物方案，都可唯一地表示为一个序列 {j1,j2,...,jn}={1,2}n\{j_1, j_2, ..., j_n\}=\{1,2\}^n，亦即，在该方案中的第 ii 份礼物选择了价格为 cjiic_{i}^{j_{i}} 者。

#### **输入格式**

第一行包含两个正整数，即 nn 和 PP。

接下来 nn 行各有两个正整数，依次给出 c1i,c2ic_{i}^{1}, c_{i}^{2}。

#### **输出格式**

仅一行，仅一个非负整数，即总花费不超过预算 PP 的礼物方案数。

#### **数据范围**

对于 50%50\% 的数据，n≤20n\le 20。另有 20%20\% 的数据，满足 0<c1i,c2i,P≤1060<c_{i}^{1}, c_{i}^{2}, P\le 10^6。对于 100%100\% 的数据，n≤40n\le 40，0<c1i,c2i,P≤1090< c_{i}^{1}, c_{i}^{2}, P \le 10^9。

#### **资源限制**

时间限制：0.6s  
 空间限制：256MB

#### **样例输入输出**

**输入样例 1**

```
2 6
2 3
5 2
```

**输出样例 1**

```
2
```

**输入样例 2**

```
5 20
5 4
5 4
5 1
2 5
5 2
```

**输出样例 2**

```
21
```

#### **注**

思考：在何种情况下满足条件的方案数最多，这个数最大可到多少？

# CST 1-2-2 Graphics

---

#### **描述**

在平面直角坐标系中，如果在 x 正半轴和 y 正半轴上分别挑选 n 个随机点，那么不难理解，只有一种方案能将这两组点一一联接起来，使得形成的 n 条线段互不相交。那么接下来，对第一象限内的任何一点 P(x,y)，联接原点 O 与 P 的线段 OP 会与这 n 条线段有多少个交点呢？

#### **输入**

第 1 行包含一个正整数 n，即随机点对的数目；  
 第 2 行包含 n 个正整数，即在 x 正半轴上 n 个点的横坐标；  
 第 3 行包含 n 个正整数，即在 y 正半轴上 n 个点的纵坐标；  
 第 4 行包含一个正整数 m，即接下来查询的次数；  
 随后的 m 行，各包含两个正整数 xix_i 和 yiy_i，即各查询点 PiP_i 的横、纵坐标。

#### **输出**

共 m 行，各包含一个非负整数，依次列出各次查询的答案。

#### **输入样例**

```
3
4 5 3
3 5 4
2
1 1
3 3
```

#### **输出样例**

```
0
3
```

#### **样例说明**

3 条线段分别为：(3, 0) - (0, 3)、(4, 0) - (0, 4)、(5, 0) - (0, 5)

(0, 0) - (1, 1)不与他们有交点，答案为 0。

(0, 0) - (3, 3)与三条线段均有交点，答案为 3。

#### **数据范围**

1 ≤ n ≤ 200,000

1 ≤ m ≤ 200,000

1 ≤ 横、纵坐标 < 2312^{31}

#### **资源限制**

时间限制：0.5 sec

内存限制：256 MB

#### **提示**

- [ 二分查找、ToLeft测试。]
- [ |对于每条有向线段，可用向量叉积的ToLeft测试，在常数时间内判断任意一点落在其左侧还是右侧。以此作为比较器，可以在多个区域中实现二分查找。]

# CST 1-2-3 二维偏序

---

#### **题目描述**

给定 nn 个三元组 {⟨ai,bi,ci⟩|1≤i≤n}\{ \langle a_i,b_i,c_i\rangle \vert 1\le i \le n \}，我们希望从中选出 kk 个并按 {ij|1≤j≤k}\{i_j | 1\le j\le k \} 排成序列，使得当 j<kj<k 时总有 aij≤aij+1a_{i_j}\le a_{i_{j+1}} 且 bij≤bij+1b_{i_j} \le b_{i_{j+1}}，并使总和 ∑kj=1cij\sum_{j=1}^k c_{i_j} 取到最大。

#### **输入格式**

第一行仅一个正整数 nn，即三元组的总数。

接下来的 nn 行各用三个整数 a,ba,b 和 cc，逐一列出各三元组。

#### **输出格式**

仅一行，仅一个整数，即题中所求的最大总和。

#### **样例 1 输入**

```
3
-1 1 2
4 3 1
2 -1 3
```

#### **样例 1 输出**

```
4
```

#### **样例 1 解释**

当 k=2k=2、i1=3,i2=2{i_1=3,i_2=2} 时，总和 3+1=43+1=4 最大。

#### **样例 2**

见样例文件的 *2.in* 与 *2.ans*。

#### **样例3**

见样例文件的 *3.in* 与 *3.ans*。

全部样例文件[点此下载](../附件/e8adea4aab8c8b636af5f826504666465ec1c6ec.zip)。

#### **限制**

本题允许使用STL

对全部输入数据，有 1≤n≤5×1051\le n\le 5\times 10^5 且 |a|,|b|,|c|≤109|a|,|b|,|c|\le 10^9

时间限制：1.0 s

空间限制：512 MB

#### **提示**

本题在当前学习阶段可能难度较高，供愿意挑战的同学选择，并在接下来提供一个较为完善的参考解法。

首先，可对三元组序列做如下预处理：

- 去掉所有 c≤0c\le 0 的项；
- 合并所有 ⟨a,b⟩\langle a, b \rangle 相同的项，合并后的 cc 取作合并前各项的 cc 之和；

不难验证，以上预处理不会破坏解的可行性，且不会减少目标函数的值。

接下来，将选出的各项按 ⟨a,b⟩\langle a, b \rangle 的字典序由小到大做排序。得益于预处理，排序的结果必然唯一。于是，aij≤aij+1a_{i_j} \le a_{i_{j+1}} 的要求便可简化为 ij<ij+1i_{j} < i_{j+1}，原问题可转化为求关于 bb 的不下降子序列，使得子序列各项的 cc 之和最大化。

可以用动态规划来求解转化之后的问题。若记 fif_i 为以第 ii 个位置结尾的合法子序列中目标函数的最大值，则转移方程为：

fi=maxj<i,bj≤bifj+cif_i=\max_{j<i,b_j\le b_i} f_j + c_i

若递推地求出所有的状态值，则时间复杂度为 O(n2)\mathcal{O}(n^2)。注意到方程中的转移条件 j<i,bj≤bij<i, b_j\le b_i 中，(j,i)(j,i) 形成关于 bb 的“非逆序对”。参照课上介绍过的基于分治的逆序对计数算法，可以导出如下基于分治的上述方程的另一解法。

对于区间 [l,r][l,r]， 定义分治子任务为求解全部满足 i∈[l,r]i\in [l,r] 的 fif_i 的值（以下简称 [l,r][l,r] 内的状态值），且要求调用该子任务时 [l,r][l,r] 内的状态值已经被 [1,l−1][1,l-1] 内的状态值更新过。设 m=⌊(l+r)/2⌋m=\lfloor (l+r)/2 \rfloor，首先可以通过递归调用求解 [l,m][l,m] 内状态值。与常规分治不同的是，接下来还不能直接通过递归来求解 [m+1,r][m+1,r] 内的状态值，因为这部分还需要被 [l,m][l,m] 内的状态值更新才能满足子任务的调用要求。

在基于分治的逆序对计数算法中，在归并序列时统计了逆序对的元素分别在两侧的情况。类似地，假设两侧的序列已经关于 bb 有序，于是也可通过按照 bb 归并的方式，用 [l,m][l,m] 内的状态值来更新 [m+1,r][m+1,r] 内的状态值。更新之后，即可对 [m+1,r][m+1,r] 对应的子任务递归调用求解。不考虑维护 bb 的有序性的成本，总时间复杂度为 O(nlogn)\mathcal{O}(n\log n)。

为保证上述归并开始时两侧的序列已经关于 bb 有序，若使用基于比较的排序算法对两侧的序列排序，则总时间复杂度会达到 O(nlog2n)\mathcal{O}(n\log^2 n)。实际上借助某种优化技巧，可以将时间成本降至 O(nlogn)\mathcal{O}(n\log n)，这一点留作思考。
