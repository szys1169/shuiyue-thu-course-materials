# CST 2-1-1 Queues

---

### **题目背景**

各种软件系统都往往需要在数据库中维护大量的队列，比如在选课系统中，每门课程都需要一个候补队列；在 12306 售票系统中，对每趟列车都需要一个候补队列。维护这些数据需要面临存储空间优化、IO 效率、数据灾备等各种问题。我们从这些场景中抽象出一个高度简化的“队列维护问题”，希望你在这个简单场景下编写的程序能满足一些简单的时间、内存限制。

为避免输入和输出效率对时间、内存占用的影响，这里采用交互形式，提供一个交互库，你只需要按要求实现一个类。

### **题目描述**

你需要在给出的实验框架中实现一个 `QueueManager` 类，对外提供如下操作接口：

- `QueueManager(unsigned int m)`： 创建 mm 个空队列，从 11 至 mm 依次编号；队列内的元素从 11 开始自前向后编号。
- `QueueManager.push(unsigned int k,unsigned int x)`： 在第 kk 个队列末尾插入 xx，1≤k≤m,x≥11 \le k \le m, x \ge 1。
- `QueueManager.pop(unsigned int k)`： 删除第 kk 个队列首元素。如果队列为空，则什么都不做。1≤k≤m1 \le k \le m。
- `QueueManager.query(unsigned int k, unsigned int i)`： 返回第 kk 个队列中的第 ii 个元素，1≤k≤m,i≥11 \le k \le m, i \ge 1。 若队列长度不足 ii，则返回队尾元素。若队列为空，则返回 0。

### **实验框架与提交说明**

请从这里下载实验框架：[framework.zip](../附件/d3527e043eeb54451ee3a9a769235ff06f328a5e.zip)，内含 `main.cpp`，`manyqueue.h`，`manyqueue.cpp`，`readme.txt`。`main.cpp` 保持不变，只能修改 `manyqueue.h` 和 `manyqueue.cpp` 以实现 `main.cpp` 所需求的功能。

命令行环境下可以用以 `g++ main.cpp manyqueue.cpp -o main` 方式编译。使用 IDE 则需要配置一个项目，包含全部源代码文件。

`QueueManager` 类的 API 已经在 `QueueManager.h` 中提供，你需要在 `QueueManager.cpp` 中, 给出 `QueueManager` API 的具体实现。

可以在 `QueueManager.h` 中为 `QueueManager` 类添加新的成员变量、成员函数，也可以定义新的类，但不得修改 `QueueManager` 原有的 API（包括函数名称、参数类型），否则会导致编译错误。

提交之前，须将 `manyqueue.cpp` 和 `manyqueue.h` 压缩为 zip文件。不必提交 `main.cpp`，即使提交了也会被统一的版本覆盖。

- 也可考虑适时地搬迁队列中的元素，以在均摊意义上满足时间、内存限制。

# CST 2-1-2 Risk

---

#### **描述**

从公元33世纪到3333世纪 ，月球城一直处于新型呼吸道疾病DIVOC-33疫情期间，每一天都是低风险、中风险、高风险三种状态之一。

DIVOC-33是一种病毒性疾病，但感染之后并不会产生永久抗体，所以可能反复感染——尽管还不致在同一天内多次反复。万幸的是，感染后的症状只是不停打嗝，并不会致死。

从首次出现确诊病例那天开始，第 ii 天的确诊病例数记作 xix_i 。借助这一基础数据，便可在选定两个阈值 0≤p<q 0 \le p < q 之后对每一天做风险度评估：对于第 ii 天，我们考查此前 mim_i 天（也就是第 i−mii-m_i 天到第 i−1i-1 天）中单日确诊病例数的最大值 kk ：如果 0≤k<p0 \le k \lt p，就将月球城评定为低风险；如果 p≤k<q p \le k \lt q，评定为中风险；如果 q≤k q \le k，则为高风险。

现在月球城安理会想知道，选用不同的阈值 p,qp, q，低、中、高风险的天数会如何变化。

#### **输入格式**

第一行仅一个正整数 nn，表示考查的天数。 第二行有 nn 个非负整数 xix_i，依次表示每天的确诊人数。 第三行有 nn 个正整数 mim_i，依次列出评估第 ii 天风险时往前追溯的天数。这里约定，第 i−1i-1 天没有追溯到的日子，第 ii 天也不会追溯到——也就是说，必有 mi≤mi−1+1m_i \le m_{i-1} + 1。 第四行仅一个正整数 TT ，表示将尝试 TT 组不同的阈值 p,qp, q 。 接下来的 TT 行各有两个非负整数 pi,qip_i, q_i，即一组阈值。

#### **输出**

共计 TT 行，各有两个整数，对应于低、中风险的天数（高风险不言而喻，不再输出）。

#### **输入样例**

```

1 2 3 4 1000 100 20
1 2 3 3 3 4 3
2
3 5
100 200
```

#### **输出样例**

```
3 2
5 0
```

#### **样例解释**

第1天前1天的确诊病例最大值为0，  
 第2天前2天的确诊病例最大值为1，  
 第3天前3天的确诊病例最大值为2，  
 第4天前3天的确诊病例最大值为3，  
 第5天前3天的确诊病例最大值为4，  
 第6天前4天的确诊病例最大值为1000，  
 第7天前3天的确诊病例最大值为1000。

取p = 3, q = 5, 低风险有3天，中风险有2天。  
 取p=100, q=200, 低风险有5天，中风险有0天。

#### **数据范围**

1≤n≤1061 \le n \le 10^6  
 每日确诊人数 xi≤2×106x_i \le 2 \times 10 ^ 6

内存：256 MB

**本题允许使用STL**

# CST 2-2-2 Polynomial

---

### **题目描述**

大 R 的妹妹小 R 上初中了，学到多项式部分的时候老师经常出一些很复杂的一元多项式展开的题，即对老师给出的涉及多种运算的多项式，最终要写成多项式的标准形式： n∑i=0aixi \sum_{i=0}^{n}a_ix^i

小 R 算出结果后不自信，总是要找大 R 检查。在多次被当“人脑计算器”使后，大 R 决定找到在星期四大学上数据结构的同学发挥编程特长，写一个程序一劳永逸地帮妹妹解决这一问题。

首先，我们可以递归地定义关于变量 `x` 的“多项式”：

- `x` 是多项式
- `[1, M)` 内的每个正整数也是多项式
- 如果 `A` 和 `B` 是多项式，那么 `A+B`、`A-B`、`A*B`、`(A)`、`A^k` 也是（kk 为正整数）

你的任务是将老师给的多项式展开，转换为多项式的标准形式。但毕竟小 R 不是程序员，她的输入可能不会符合程序员的严格风格，而更贴近书写习惯，因此你的程序需要充分考虑小 R 的输入习惯与老师的要求。

- 小 R 不喜欢在运算符两侧加上空格，因此你得到的输入是没有冗余空格的紧凑字符串；
- 涉及到的运算符包括加号 `+`、减号 `-`、乘号 `*`、次幂号 `^`、小括号 `()`。好消息是，在多次交涉后，小 R 终于同意了只使用小括号来表示嵌套，因此你不会见到中括号、大括号等其他类型的括号，运算符之间的优先级顺序与[讲义](https://dsa.cs.tsinghua.edu.cn/~deng/ds/src_2025/evaluate/priority.h.htm)一致，尤其需要注意的是，次幂号 `^` 为左优先结合；
- 多项式中的变量统一为字母 `x`；
- 次幂号的右边一定是正整数；
- 括号内部不为空；
- 数值总是最高位不为 00 的正整数（于是 00 和负数不会作为系数出现，但不要忽略减法）；
- 某些情况下小 R **可能**会偷懒省略乘号，但仅限于如下几种情况：  紧靠于乘号右边的是左括号； 紧靠于乘号右边的是 `x`，同时左边不是 `x`（比如 `3(2+1x)x*x` 是合法的，而且最后那个乘号不能省略）；
- 除了乘号可能省略，小 R 保证输入内容绝对是合法多项式，绝不会出现未定义的表达式，比如 `x^(3)`（次幂部分不应出现运算符）或 `(1+(2x+3)`（括号失配）之类。
- 标准形式多项式中的系数可能非常大，为便于老师检查这里统一约定，每个系数都需要对一个固定的正整数 `M` 取模，转换为 `[0,M)` 内的一个整数。  特别地，若取模后最高位为 0，则该位不需要输出。例如 P(x)=Mx2+(M+1)x+1≡x+1(modM)P(x) = Mx^2+(M+1)x+1 \equiv x+1 \pmod M，故只需输出多项式 x+1x+1 对应的系数。

### **输入**

只有一行字符串，所有字符均取自 `0123456789x-+*^()`，末尾以 `\n` 结束。

### **输出**

如果是 kk 次多项式，你就需要按照次数由高到低地输出 k+1k+1 个各项系数，以空格相隔。

特别地，如果结果为 00，则直接输出 `0`。

### **输入样例**

```
((2)*x*x+1)^2-(2x^2)^1^2^1-3x^3
```

注：此样例是第 11 个测试点。

### **输出样例**

```
1000000004 4 0 1
```

### **样例说明**

(2x2+1)2−(2x2)2−3x3=−3x3+4x2+1≡1000000004x3+4x2+1(modM) (2x^2+1)^2-(2x^2)^2-3x^3=-3x^3+4x^2+1\equiv 1000000004x^3+4x^2+1 \pmod M

### **数据范围**

输入字符串的长度 0<n≤10000000 < n \le 1000000

#### **算法描述**

以图4中由 1717 个节点构成的 xx-单调多边形为例。其中内角不小于 π\pi 的节点，称作优节点（reflex vertex），其余称作劣节点（non-reflex vertex）。除首、尾节点外完全由优节点组成的多边形链，称作优链（reflex chain）。

这里采用扫描线算法：假想着有一条竖线从左而右地扫过n边形，逐一处理遇到的每个节点，并贪心地通过连接当前节点和某个此前已经扫过的节点，引入一些**对角线**。每引入一条对角线，都相应地切出一个三角形。为此，需要使用一个栈 SS，来记录多边形在当前扫描线左侧——虽已扫过却仍待处置——的那部分。作为算法的一项不变性，SS 中的节点总是来自于同一条单调链，且构成一条优链。

在处理每个节点 viv_i 时，算法无非分三种情况作相应的处理：

情况1. 若 viv_i 与 SS 中节点不属于同一条单调链，则 SS 中每个节点与 viv_i 之间的连边，必然都是一条内对角线。于是，我们便可以在清空 SS 的过程中引入这些内对角线，再令原先的栈顶节点和 viv_i 入栈；

情况2. 若 viv_i 与 SS 中节点同属一条单调链，则又可细分为两种子情况：

(a). 若栈顶 vi−1v_{i-1} 为优节点，则令 viv_i 入栈；

(b). 反之若栈顶 vi−1v_{i-1} 系劣节点，则可弹出 vi−1v_{i-1} 并引入内对角线 vi−2viv_{i-2}v_i。这种情况可能重复多次，直至转入子情况(a)，或者栈中已不足两个节点（算法终止）。

请自行证明：算法执行的过程中，以下不变性始终满足： **不变性.** ∀i≥2\forall i\ge 2，令 viv_i 是算法刚处理过的节点。viv_i 左侧尚未剖分的区域由两条 xx-单调链构成：其一为优链，恰好存放在辅助栈中；另一条链只有一条边，其左端点栈底节点 uu，而右端点在 viv_i 右侧。

其中，第一个非负整数为通路的长度 mm（22），随后的 mm 个非负整数依次列出了通路上各个节点在（亲）兄弟中的**排行**次序（rank，从 00 开始）：先从根节点转向它的第 11 个孩子（节点 22），再从节点 22 转向它的第 22 个孩子（节点 77）。

当然，反过来，**形式上**合法的这样一行数字，未必是**实际上**合法的：对应于一条真实存在的通路（及其终点）。以下就是这样的一例：

```
3 1 2 3
```

这行的第一个整数 33 意味着一条长度为 33 的通路，而上图所示的多叉树高度仅为 22 ，故这条通路并不存在。再如：

```
2 0 1
```

虽然根节点有长子（第 00 个孩子，节点 33），但节点 33 并没有次子（第 11 个孩子）。

我们约定，**形式上**合法的任何一条通路，都等效地被理解为其**实际上**合法的最长前缀。于是，上述实例中的两条通路，依然可以分别理解为与节点 77、节点 33 相对应。

#### **子树移动**

所谓的在多叉树中将某一棵**真**子树 ss **移动**到目标位置 (d,k)(d,k)，是指先将 ss 从树中分离出来（类似于 05-B2 节的 `Bintree::secede()`），再将其接入到节点 dd 下面，作为 dd 的第 kk 个孩子（类似于 05-B2 节的 `BinTree::attach()`）。

这里约定，ss 和 dd 均用**通路表示法**来指定；kk 则用一个非负整数来指定。

仍以上面的多叉树为例，将子树 ss：

```
2 0 0
```

移动到节点 dd：

```
1 1
```

之下作为孩子，且排行 kk 为：

```
0
```

多叉树将相应地演变为：

![](../附件/5233545de6add4c06800a2f102368dd27c85db86.png)

为消除当 `s->parent == d` 时可能的歧义，这里约定：kk 是就 ss **刚分离之后**的时刻而言的。此外，dd 的通路表示也是就 ss 分离后的时刻而言的。

比如对于最初的实例，将子树 ss：

```
2 1 1
```

移动到节点 dd：

```
1 1
```

之下作为孩子，且排行 kk 为：

```
2
```

所得到的多叉树应为：

![](../附件/b0adebe45efbac5349fdb8e9973892f0b1e85f74.png)

每次子树移动操作的**成本**，等于节点 ss 和 dd 按照**通路表示法**所对应的两行中所有整数的总和，再加上 kk 。比如，上例中操作的成本为： (2+1+1)+(1+1)+2=8 (2 + 1 + 1) + (1 + 1) + 2 = 8

#### **查询**

任何时刻，我们都可能查询任何节点（子树）的**高度**或**规模**，其定义详见讲义。每次查询操作的**成本**，等于被查询节点按照**通路表示法**所对应的那一行中，所有整数的总和。

仍以上面的多叉树为例，查询节点（子树）:

```
2 1 1
```

对应高度的操作成本为： 2+1+1=4 2 + 1 + 1 = 4

### **输入**

第一行为两个整数：NN（多叉树中的节点总数）、MM（移动和查询操作的总次数）。

随后的 NN 行，以**孩子节点表示法**给出一棵多叉树。

接下来的各行，依次描述 MM 次操作：

- 移动操作以连续的 44 行描述：首行仅一个整数标志 00，随后三行分别指定 ss、dd 和 kk；
