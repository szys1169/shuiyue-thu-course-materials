大作业过程分细则
Last Update @ 2026-09-11
课上指导
• 在第3至12周的开发进程中，每周均设置助教的课上指导环节（除十一放假外，共计9次）
• 在大作业开发过程中，以小组形式参与课上指导环节，任何成员不得无故缺勤，如有需要提前向
 助教请假
需求交付
• 软件开发过程中，需要定期在课上指导环节前向助教交付阶段性成果。
• 每次课上指导环节前，需要向助教提交本次计划交付的功能清单（按需求文档中的功能为准）
• 课上需要演示所有计划交付的功能，助教也会对这些功能进行测试
• 一旦功能交付，则应当在主分支中保持可用

过程管理细则
课上指导环节
• 缺席已经确认的课上指导环节
 ◦ 该成员 -2
 ◦ 如果事先请假得到批准的，不扣分
• 演示时部署不可用
 ◦ 所有成员 -1
 ◦ 例如主分支部署网址无法访问等
• 交付的功能演示失败
 ◦ 所有成员 -1
    ▪ 只是小 bug 不会扣
 ◦ 每次课上指导最多扣分 1 次
• 助教发现主分支中已交付功能存在 bug
 ◦ 所有成员 -1
  ◦ 与上条一起，每次课上指导最多扣分 1 次

CI/CD
• 后端单测覆盖率低于 80% (从第 6 周开始，在课上指导环节检查)
  ◦ 所有成员 -1
  ◦ 前端单测覆盖率不做要求
• SonarQube 警告，助教复查确有隐患，且指出一周后仍未修复的
  ◦ 所有成员 -1/每次
• 代码质量存在严重问题，助教检查指出后在下一次课上指导环节时仍未修复的
  ◦ 该成员 -0.5/每次
  ◦ 每次课上指导最多扣分1次

Git
• Commit Message 不合规范
  ◦ 该成员 -0.5
• Branch Name 不合规范 / Merge Request 不合规范 / 合并后未删除旧分支 / 直接修改主分支
  ◦ 该成员 -0.5
• 单个 Commit 修改行数大于 500
  ◦ 该成员 -0.5
对于每位成员，发现第一次违规时仅提醒，从第二次发现（含第二次）开始扣分
工作量
• 小组合理分工是软件工程的重要内容，我们反对单人贡献比例极高或极低的分工。
• 工作量不均衡、贡献极低、态度消极、多次不参加集体讨论等
  ◦ 扣分情况一事一议
  ◦ 原则：及时向助教提出，广泛接受举报，听取全组意见
